# 给 WikiReader 生成文章的规范

> **谁该读这份文档**：任何会话里，只要要"生成一篇文章给 WikiReader 朗读/学习"，就按这里写。
> 文章通过 App 的 **+ → Import → File… / Photos… / Paste Text** 导入（见 PROGRESS.md "导入本地文章"）。
> App 会把文本拆成"标题 + 段落"块，**朗读（TTS）、逐词高亮、点词查词典、书签、翻译都以段落为单位**，所以段落怎么切直接决定听感。

## 1. 交付形式

- 一个 **UTF-8 的 `.md` 或 `.txt` 文件**（也可以直接贴文本）。PDF、截图/照片也能导入，但文本文件最准、最省事，**优先给 `.md`**。
- 文件名用英文标题，空格换成下划线，例如 `The_Tea_Trade.md`。文本里没有 `# 标题` 时，App 用文件名当文章标题。
- 一个文件一篇文章。

## 2. 结构

```markdown
# The Tea Trade

Opening paragraph, two to five sentences.

## Early Years

A paragraph about one idea.

Another paragraph.

### A Smaller Topic

...
```

- **第一行 `# 标题`，且全文只有这一个 `#`。** 它成为文章标题，不会被当作正文朗读。（如果有多个 `#`，App 不再把它们当标题，而是都当作章节。）
- 章节用 `##`，子节用 `###`，最多到 `####`。每 3–8 个段落一个章节比较舒服。
- 标题是简短的名词短语，不以句号结尾，不加编号（`1.`）、emoji 或 Markdown 强调。
- 标题会被朗读，之后停顿一下，所以标题要念得出来。

## 3. 段落

- **段落之间空一行；段落内部不要手动换行**（一段一行）。App 会把相邻的行并成一段，但 Markdown 里硬换行容易造成误并。
- **一段一个意思，约 2–6 句、不超过 ~120 个单词。** 朗读按段生成语音、按段缓存、按段预取；太长的段落启动慢、跳转不便，超过 4096 字符会被强行切开。
- 句子写完整，用常见标点收尾（`.` `?` `!`）。

## 4. 只放要读的内容

App 会**丢弃或去掉**这些，所以不要依赖它们表达意思：

| 写法 | App 的处理 |
|---|---|
| 表格（`\| a \| b \|`） | **整行丢弃**（朗读表格没意义），预览页会提示丢了几行 |
| 代码块（```` ``` ````） | 丢弃 |
| 图片 `![]()`、HTML 标签、脚注 `[^1]`、`[1]` 引用 | 去掉 |
| 分隔线 `---`、`***` | 去掉（当作段落分隔） |
| `**粗体**`、`*斜体*`、`` `代码` ``、`[文字](链接)` | 只保留文字，格式丢掉 |
| 列表 `- ` / `1. ` | **每一项变成一个独立段落**（单独停顿、单独高亮） |
| `> 引用` | 去掉 `>`，当普通段落读 |

所以：
- 不要用表格、代码块、图片；确实要列东西，用**短列表**，每项是完整的词组或句子。
- 不要在正文里放 URL、邮箱、emoji、`[citation]` 之类读起来很怪的东西。
- 强调不要靠加粗，靠措辞。

## 5. 适合朗读的写法

- 缩写和符号写成能自然念出来的形式：`for example` 而不是 `e.g.`，`about` 而不是 `~`，`percent` 比 `%` 更稳。
- 数字：年份、小数写阿拉伯数字没问题（`1999`、`3.5`）；长串数字、电话、公式不要放进正文。
- 括号里的长插入语会让朗读断气，能拆成两句就拆。
- 一个句子一个主干，避免超过 35 个词的长句。
- 破折号、冒号、引号都可以用。

## 6. 英语学习类文章

用户的文章大多是**用来学英语**的。目前约定：

- **正文纯英文。** 不要在同一段里混中文；朗读用的是英文声音，中文会读得很糟。
- 词汇表、练习题、中文释义这类"学习辅助"内容：**单独放在文章末尾的独立小节**（例如 `## Vocabulary`、`## Questions`），不要穿插在正文段落里，并在交付时告诉用户里面有这些小节。
- ⚠️ **App 目前还没有针对这类小节的特殊朗读支持**（比如跳过中文、跳过练习题、词汇表逐项朗读）：现在它们会被当成普通段落读出来。用户说过之后会让 App 增加这类朗读支持，**届时本节的约定会更新**——生成文章时先照上面写，不要自作主张发明新标记。

## 7. 长度

- 单篇 300–1500 个单词比较合适（约 2–10 分钟）。更长的请拆成几篇，各有自己的 `# 标题`。

## 8. 交付前自检

- [ ] 第一行是 `# 标题`，全文只有一个 `#`
- [ ] 章节用 `##`/`###`，没有编号和 emoji
- [ ] 段落之间一个空行，段落内部没有硬换行
- [ ] 每段 ≤ ~120 词，每句不过长
- [ ] 没有表格、代码块、图片、URL、脚注、HTML
- [ ] 列表只在必要时用，且每项是完整短语
- [ ] 正文全是英文；学习辅助内容在末尾独立小节里，并已告知用户

## 附：App 怎么解析（给开发会话看）

代码在 `WikiReader/Services/Import/`：
- `LocalArticleParser`：文本 → 标题 + `[ContentBlock]`（上面第 2、3、4 节的规则；测试在 `LocalArticleParserTests`）。
- `PDFTextExtractor` / `ImageTextRecognizer` + `TextLineAssembler`：PDF（PDFKit，扫描页走 Vision OCR）和照片（Vision）→ 带 `#` 标题标记的文本，再交给同一个解析器。标题靠字号/加粗判断，段落靠行距、行尾标点判断。
- `FileTextExtractor`：按扩展名分派，读取文本文件（UTF-8/UTF-16/Windows-1252）。
- 导入后先进入预览页（`ImportDraftView`）可改标题和文字，再保存为 `Article`（`origin == "imported"`）。
